## Deployment contract and limits

Apply the migration once as a separate migration owner in an empty, dedicated Evidence database. It intentionally is not a general upgrade runner: the operator must version/serialize migrations and never apply it to the unrelated recovered database. It revokes PUBLIC CREATE on public and creates the restricted role, so the migration account needs the corresponding administrative privileges. The runtime account must never own the database's Evidence tables or have access to the migration owner's role. Keep migration credentials outside the application runtime.

Provision a separate LOGIN with no superuser/BYPASSRLS/CREATEDB/CREATEROLE/REPLICATION attributes and NOINHERIT; grant only membership in `evidence_runtime` with permission to SET ROLE. Supply its secret through deployment configuration to `postgresDatabase`. The migration deliberately contains no passwords, sample credentials or live infrastructure provisioning. `scoped` validates the session each transaction; pg's driver uses BEGIN/COMMIT/ROLLBACK and returns broken connections to the pool with destruction after rollback failure.

The `Database`/`Query` interfaces and `postgresDatabase` factory are trusted driver infrastructure. Only pass UnitOfWork to command handlers. A database credential holder able to run arbitrary SQL can change custom scope settings; GUC-based RLS is defense in depth for a trusted service, not authentication or protection from arbitrary SQL execution. Obtain Context and authoritative time from Identity/a trusted service boundary. A LeasedJob is a scoped work handle, not a signed security capability. Only await sequential operations inside a unit; different projects can progress independently, while the project lock intentionally serializes writes and claims within a project.

The idempotency callback must contain database work only: external effects cannot be rolled back and belong in outbox consumers. Outbox delivery is at least once; workers need idempotent external-effect keys. A generation fence prevents stale database state changes but cannot undo an external effect already issued by an expired worker. No production worker/scanner service is included.

Metadata transactions do not atomically include encrypted filesystem/object-store writes. Persist/verify an immutable object receipt before metadata publication and reconcile orphaned objects separately. This PR implements generic persistence primitives, not a complete service, scanner, object transaction coordinator or live deployment. Pool/network authentication, true multi-session contention, crash recovery under power loss, migrations on managed PostgreSQL, backup/restore and live service acceptance remain unverified.

## Primary references consulted

- [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html): owners/superusers, FORCE RLS, and table-wide operations outside RLS.
- [PostgreSQL SET ROLE](https://www.postgresql.org/docs/current/sql-set-role.html): session_user retains role-switch authority after current_user changes.
